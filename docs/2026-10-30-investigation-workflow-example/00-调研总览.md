## 目的

本 Topic 是 `monospec-example` 的示例内容：把来源项目中一次成功的 FEV / ICD 案例复盘（2026-10-30）整理成与业务无关的工作方式参考。目标项目采用模板时，可用它理解各 Trait 如何在一项真实任务里衔接；示例不代表目标项目已完成任何验证。

## 范围

- 包含：工作链、文档分工、阶段结束回填、handoff 核对、Human / Agent 决策边界、候选执行说明与验证方法。
- 不包含：来源项目的业务名称、模型数据、session transcript、commit、Run 结果与产品状态。
- 不修改：根 / subtree `AGENTS.md` 的现行规则、Trait 正文与 `project-template/` package。

## 核心结论

1. 可复用的是一条有上下文的工作链：**用户目标 → 当前差距 → 整体路线 → 局部实验 → 回填设计与知识 → 下一项实验 → Promotion → production ICD**。详见 [01](01-工作链与文档分工.md)。
2. 文档职责在开始时就要分好（baseline、target、design、Evidence Analysis、Promotion），不要等到最后再整理。文件数量和编号按实际用途定，不需要照搬。
3. 用户目标的修正是来源案例的关键转折点。范围变化必须写进 design 与 Graph contract，只在聊天里答复不够。
4. 来源案例并非全程无人介入：用户修正目标、选择阶段、批准 Promotion；Agent 负责局部修复、结果回填、上游重跑、跨会话状态核对，以及 Promotion 后的 production ICD。
5. 一个按这条工作链执行的可运行案例见 [Example Character Blender → UE5](../2026-10-30-example-character-blender-ue5/00-调研总览.md)：目标收窄、Negative Finding 修正 contract、Promotion、production 与 ICD 都有对应 artifact。
6. 这套方法目前是候选，尚未在其他任务中验证效果。执行说明见 [02](02-执行说明与验证.md)，skill 草案见 [03](03-Investigation-Skill-Draft.md)（未安装）。

## 关键发现与 Knowledge State

| 内容 | State | 依据与限制 |
|---|---|---|
| 来源案例的工作链、文档分工和阶段回填确实发生过 | CONFIRMED | 来源项目已用会话记录、Git history 与 Run 交叉核对；本仓不保存这些记录 |
| 上述做法是来源案例成功的原因 | INFERRED | 没有 controlled comparison；任务范围与授权差异也有影响 |
| 不同模型之间的效果差异 | UNKNOWN | 没有相同任务、环境与授权的对照 |
| 本示例的执行说明能改善其他任务 | PENDING_VALIDATION | 需要在明确授权的真实任务中试用后判断 |
