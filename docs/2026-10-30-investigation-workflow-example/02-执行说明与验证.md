# Investigation Workflow — 执行说明与验证

```yaml
doc_type: REFERENCE
lifecycle: ACTIVE
knowledge_state: PENDING_VALIDATION
date: 2026-10-30
authority: 候选执行方法；不是 repository policy，不扩大用户授权
```

## 适用范围

适用于跨阶段、有重要 runtime uncertainty 的 investigation。普通修改、单纯资料查询或已验证的修复不需要完整流程。行为依据见 [01](01-工作链与文档分工.md)。

## 执行说明

可以把下面这段直接放进任务请求或 handoff：

```text
按项目 AGENTS.md 和适用的 FEV / ICD / DOCS / CED contract 执行。
保持目标、实验、知识与实现之间的连续关系。

1. 先确认当前用户目标、已决定范围、非目标、授权边界；读取相关
   Topic Summary 和实际 Graph / change 状态，纠正过时的 handoff。
2. 以目标和当前差距组织整体路线。指出哪些已知、哪些需要实验、
   哪些依赖用户决定。复用已有 Evidence，不从零重建。
3. 选择当前最能减少目标不确定性、且依赖已满足的问题。
   设计最小、有区分力的实验；记录它如何影响整体路线。
4. 执行、分析并处理普通故障。必要时换路径或修正上游；
   依赖变化后更新受影响的输入与 Evidence，不把局部完成当作整体完成。
5. 每个有意义的阶段结束时，把结果放回整体目标：改变了什么、
   仍未知什么、下一步是什么。更新实际受影响的设计、Topic Summary
   与 Evidence 引用；保留 authority，不逐轮复制聊天。
6. 在已有授权内继续依赖已满足的工作。用户明确要求 checkpoint 时
   遵守；真正改变范围或缺少必要决定时，给出具体选择、推荐与影响。
7. feasibility 问题回答后，形成实施建议。只有取得 Promotion 授权
   才进入业务代码；对 production 实现独立执行 ICD。
8. 中断或换 Agent 时，交接目标、决定、实际状态、可靠入口、
   运行条件、Negative Findings、下一步及授权边界。
```

这段说明不扩大用户授权，也不把 DOCS 变成 task tracker。Epic state、Verdict 与 Acceptance 仍由各自的 owner 持有。

## 阶段结束时的汇报

按以下信息组织即可，不需要固定标题：

- **目标进展：** 本阶段回答了哪个问题，对整体目标有什么影响。
- **依据：** 关键结果与可复查的来源（Run identity、文件、commit）；不罗列全部 tool call。
- **变化：** 设计、输入或先前结论是否需要调整。
- **下一步：** 在当前授权内直接继续，或说明需要的决定及其影响。

## Handoff 内容

| 项 | 说明 |
|---|---|
| 目标与决定 | 用户目标、非目标、已做出的决定及日期 |
| 可靠入口 | Topic Summary、Graph、OpenSpec change 的路径 |
| 实际状态 | 已完成的 stage 及其 Run identity；未完成的部分 |
| 运行条件 | 执行所需的 host、engine 版本、Worker（只写逻辑名，不写凭据） |
| Negative Findings | 已排除的路径及原因 |
| 下一步与授权 | 下一项工作；是否需要先询问用户 |

接手的 Agent 仍须先核对当前事实，再按 handoff 行动。

## 效果验证

验证的对象是工作过程和用户得到的结果，不是生成相同的目录。选择一项复杂度相近、明确授权执行的真实任务；开始前记录目标、环境与已知 baseline，结束后观察：

| 维度 | 可观察结果 |
|---|---|
| 目标连贯性 | 每项主要实验都能说明与用户目标的关系；范围修正进入实际设计 |
| 调查推进 | 普通故障得到处理；授权内有价值的下一步被继续执行 |
| 知识积累 | 新结果被下一阶段使用；Summary 与设计能帮助另一个 Agent 接续 |
| 决策质量 | 询问对应真实的用户选择，并附具体结果、推荐与影响 |
| 实现交接 | 区分实验结论、Promotion 与 production ICD，并说明实际完成边界 |
| 用户体验 | 用户较少需要重复提醒核心目标、继续执行或更新文档，同时保留必要的控制 |

比较不同 Agent 或模型时，应使用相同的输入、工具条件、授权和任务范围，并单独记录用户介入。单个任务的结果只支持该任务范围内的结论。
